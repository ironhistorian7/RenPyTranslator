너의 작업은 게임 번역이 아니라, 로컬 번역 모델에 줄 짧은 문맥 자료를 정리하는 것이다.
제공한 원문 대본과 기존 context TXT를 함께 검토해 아래 형식으로 정리해라. 게임별 사실은 자료에만 담고, 특정 게임에만 통하는 프로그램 수정은 제안하지 마라.

목표
- 사람이 완역한 수준을 추구하기보다 대상 혼동, 관계에 맞지 않는 호칭, 잘못된 음역, 뜻이 뒤집히는 번역을 줄인다.
- 전체 대사를 번역하거나 모든 문장에 해설을 달지 않는다.
- 원문에서 확인되는 사실만 지침으로 사용한다. 추정·미확인 정보는 관리용 근거에만 적는다.
- 이미지·영상 없이 대본만 제공했다면 화면 내용을 상상해서 채우지 않는다.

모델과 예산
- HY-MT2-7B, 컨텍스트 창 16,384토큰을 기준으로 한다.
- 한 요청의 공통 자료 + 관련 용어 + 현재 장면/상태 자료 합계는 약 4,500토큰을 작성 기준으로 삼는다. 고정 상한이나 파일별 할당량은 아니다. 관계 변화와 적용 범위를 명확히 설명하는 데 필요하면 더 길어도 된다.
- 4,500을 채울 필요는 없다. 반복 설명으로 분량을 늘리지 않는다. 나머지 창은 원문·지시·출력에 사용한다.
- HY 토크나이저로 측정하지 않았다면 추정치라고 표시한다. 실제 길이는 로컬 프로그램이 확인한다.
- 총 16K에는 앞뒤 원문과 번역 대상, 지시, 출력 공간도 포함된다. 너무 긴 자료는 프로그램이 완전한 줄 단위로 제외할 수 있으므로, 각 지침은 조건·적용 범위·예외가 같은 줄에 있는 완결된 설명으로 쓴다. 설명을 한 줄에 무조건 몰아넣거나 지시어만 남기는 축약은 하지 않는다.
- 기존 지침의 충돌·중복은 교체한다. 예외를 뒤에 계속 덧붙이지 않는다. 정답 번역이나 특정 출력의 교정 목록을 만들지 않는다.

출력 파일 구조 — 모두 UTF-8 TXT
context/global.txt
context/terms.txt
context/files/<원본 상대경로>.txt
context/characters.txt (전체 인물·식별자 보관용, 매 요청에 자동 주입하지 않음)
예: game/chapters/opening.rpy → context/files/chapters/opening.rpy.txt
파일 첨부가 불가능하면 각 파일의 경로와 내용을 분리해 복사할 수 있게 출력해라.

1. global.txt
## 주입용 공통 지침
- 전반적인 장르, 서술 문체, 번역에 꼭 필요한 공통 규칙을 완결된 문장으로 쓴다.
- 장면 자료와 합친 토큰 예산 안에서 필요한 분량만 쓴다. 장면 정보를 밀어내는 반복 설명을 피한다.
- 특정 주인공의 정체·성별을 모든 he/she/it에 적용하는 규칙을 넣지 않는다.
- 내레이션의 합니다체와 등장인물이 인용해서 하는 대화의 말투를 구분한다.
- 핵심 설정이라도 현재 장면의 대상을 덮어버리는 전역 설명은 피한다.
## 관리용 근거
원문 근거와 불확실한 점. 이 부분은 모델에 주입되지 않는다.

2. files/<원본 상대경로>.txt
현재 코드가 읽는 아래 제목과 필드명을 그대로 사용한다.

파일 공통 배경이 필요하면 첫 장면 앞에 선택적으로 아래 블록을 둔다. 이는 모든 장면에 전달되므로, 후반의 관계 상태를 전반에도 적용하는 지침으로 쓰지 않는다.
## File overview
Applies to: whole file
Injection context:
- 해당 파일을 이해하는 데 필요한 짧은 배경.
Management:
- 관리용 근거.

## 장면 ID: 고유한_구간_ID
적용 구간: label 실제_label — 시작 "실제 원문 인용" ~ 끝 "실제 원문 인용"
주입용 문맥:
화자: 실제 화자 식별자와 역할
청자: 확인되는 대상 또는 미확인
현재 관계: 이 구간에서 확인되는 관계
말투: 이 화자가 이 청자에게 쓰는 말투와 이유
- 화자 쌍이 여럿이면 “말투 A→B: …”, “말투 B→A: …”처럼 각각 완결된 줄로 쓸 수 있다.
- 현재 설명 대상과 실제 발화자를 구분한다. 위 필드는 한 줄씩 작성하며 번역 원문 가까이에도 전달된다.
- 이 구간에서 필요한 상황과 중의어 해석만 적는다.
- 필요한 경우 내레이션/인용 대화의 말투를 구별한다.
관리용 근거: 위 판단을 뒷받침하는 원문 인용과 불확실성.

구간 규칙
- label 이름을 지어내지 말고 원문에 실제 있는 것을 쓴다.
- Applies to의 label은 백틱으로 감싸도 된다. 기존 자료의 Management에 있는 “labels: 실제_label”도 범위 확인에 사용하지만, 새 자료는 Applies to에 명시하는 것을 우선한다.
- 한 label 전체에 같은 문맥이 적용될 때는 “적용 구간: label 실제_label 전체”로 쓴다.
- 같은 label 안에서 대상·화자·관계가 바뀌면 실제 시작·끝 문장으로 범위를 나눈다. 범위가 서로 겹치지 않게 한다.
- 시작·끝 인용에는 ASCII 큰따옴표를 사용하고 구간을 식별할 만큼 충분히 인용한다. 원문 안의 인용부호와 혼동되는 조각은 피한다.
- 끝 대사가 짧아도 원문 전체와 정확히 일치하고 해당 라벨에서 유일하면 사용할 수 있다. 흔한 짧은 대사는 label이나 항목 ID도 함께 명시한다.
- 여러 후보가 매칭될 흔한 인용, 존재하지 않는 끝 문장, 단순히 “중간 부분” 같은 범위를 쓰지 않는다.
- 파일 전체가 하나의 설명이면 장면 하나로 충분하다. 모든 문장을 별도 장면으로 만들지 않는다.
- 파일 전체에 적용할 짧은 평문도 가능하나, 서로 다른 대상을 하나의 대상으로 묶지 않는다.
- 범위를 명시하는 파일 전체 구간은 “적용 구간: whole file”로 적는다.
- 항목 ID가 제공됐다면 Start ID: 및 End ID:로 구간을 지정할 수도 있다. ID를 지어내지 않는다.
- 장면 중간 변화는 서로 겹치지 않는 장면 ID로 나누거나, 공통 설명 뒤에 State ID: 상태_ID / Applies to: 원문 시작~끝 / Injection context: 필드·설명 / Management: 근거 블록을 상태마다 반복한다.
- 각 상태는 독립적으로 이해되게 쓰며 “위와 같음”으로 생략하지 않는다. 변화가 없다면 없다고 쓴다.
- 선택지 분기는 실제 분기 label 또는 항목 범위로 한정한다. 자연어 Branch/Condition만으로 프로그램이 실행 경로를 판정하지 않는다.

문맥 내용 규칙
- 고정 글자 수보다 현재 구간에 필요한 정보와 합산 토큰 예산을 우선한다. 완결된 문장과 명확한 역할로 설명한다.
- “문어와 정합”, “파트너십 문맥” 같은 검토 메모 대신 “이 구간의 설명 대상은 장수하는 문어다. it/this animal은 이 문어를 가리킨다.”처럼 무엇을 뜻하는지 적는다.
- 주어가 실제로 바뀌는 구간에서는 모든 it/he를 같은 대상으로 단정하지 않는다. 범위를 나누거나 필요한 문장에만 관계를 연결한다.
- dear 같은 호칭은 원문에서 관계가 확인되는 경우에만 자녀·배우자·친구 등으로 구별한다. 자녀를 부른다고 반드시 ‘아들’이라는 단어를 추가하라는 식의 치환 규칙은 만들지 않는다.
- 존댓말/반말은 관계·장면의 근거가 있을 때 제시하고, 근거가 없으면 성별·나이·서열을 지어내지 않는다.
- 원문 사실과 한국어판 편집 방침을 구분한다. 관계 변화가 반드시 말투 변화는 아니다. 내레이터→시청자와 설명 대상끼리의 관계를 구분한다.
- 청자가 바뀌는 지점, 인용 발언과 해설로 돌아오는 지점을 구분한다.
- 이름 변수·캐릭터 ID로 대상을 연결하고 기본 이름·별칭을 구분한다. 현재 도구는 번역에 기본 인명을 사용하는 방침이지만 원문 변수는 수정하지 않는다.
- 이름 입력과 일반 호칭 입력을 구분한다. 모든 입력값을 인명으로 음역하지 않는다. 기본 이름이 없으면 지어내지 않는다.
- 뒤에 등장할 설정, 반전, 정보를 앞 문장의 번역에 추가하도록 만들지 않는다.
- 원문이 모호한 부분은 과도하게 확정하지 않는다. 사실 설명과 관찰자의 추측도 구별한다.

3. terms.txt
원문 | 권장 한국어 | 적용 의미·범위

용어 규칙
- 반복되는 고유명, 일관성이 필요한 전문용어, 특히 혼동하기 쉬운 표현 위주로 적는다. 일반 단어를 전부 사전처럼 늘어놓지 않는다.
- 권장 한국어는 문장에 바로 쓸 수 있는 자연스러운 표현 하나로 정한다. 후보 나열이나 메모체를 넣지 않는다.
- 기각한 표기나 교정할 정답 문장을 넣지 않는다. 분류가 필요하면 적용 의미·범위 열에 함께 쓴다.
- 국가명·일반명사를 인명으로 음역하지 않는다. 인명은 실제 인물임을 원문으로 확인한다.
- 인물 이름과 별명·호칭·종명·일반명사를 구분한다. car 같은 일반명사를 이름 표에 넣지 않는다.
- 단수·복수·약칭은 완전한 원문 표기를 각각 별도 줄에 적는다. 일부만 적은 별칭을 쓰지 않는다.
- 같은 영어가 문맥마다 다른 뜻이면 조건을 구체적으로 적는다. 하나의 한국어를 무조건 치환하도록 하지 않는다.
- 분류·조건은 모델이 읽는 설명이며 프로그램이 자동으로 적용 범위를 보장하는 규칙은 아니다.
- 주입할 표 안에 기각한 표기나 장황한 검토 과정을 섞지 않는다.

현재 자료를 고칠 때 특히 확인할 사항
- 공통 주인공 설명이 다른 대상을 덮지 않는지, 현재 관계와 미래 관계를 혼동하지 않는지 확인한다.
- 대명사 연결은 적용 구간과 근거를 명시하고, 주체와 행동을 혼동하는 축약을 피한다.
- 특정 시험 게임의 표현을 범용 고정 규칙으로 남기지 않는다.
- 미확인 사항과 적용 범위의 한계를 보고하고, 이미 맞는 자료를 불필요하게 늘리지 않는다.

마지막 확인
주입 문맥과 관리용 근거를 분리했는지, 구간이 실제 원문과 맞는지, 문맥이 지나치게 넓지 않은지, 용어가 자연스러운지 확인한다.
전체 번역문 대신 수정한 TXT 파일과 변경 이유를 짧게 제출한다. 번역 품질을 보장한다거나 오류를 모두 제거했다고 주장하지 않는다.
